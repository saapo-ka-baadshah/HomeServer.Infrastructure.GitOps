# Architecture Constraints

*Last verified against repository state: 2026-09-15.*

## Technical Constraints

The technical constraints are defined in [specs/REQUIREMENTS.md](../../specs/REQUIREMENTS.md) §4 and listed below.

| ID | Constraint | Description |
|----|------------|-------------|
| CON-001 | Flux Version | Flux v2.9.5 (source-controller v1.9.5, kustomize-controller v1.9.5, helm-controller v1.6.4, notification-controller v1.9.4). |
| CON-002 | Kubernetes API Versions | Uses `source.toolkit.fluxcd.io/v1`, `kustomize.toolkit.fluxcd.io/v1`, `kustomize.config.k8s.io/v1beta1`, `networking.k8s.io/v1`, `rbac.authorization.k8s.io/v1`, `apiextensions.k8s.io/v1`. |
| CON-003 | Kustomize API | `kustomize.config.k8s.io/v1beta1` (not v1beta2 or v1alpha1). |
| CON-004 | Cluster Naming Convention | Clusters live under `clusters/<cluster-name>/flux-system/` with `gotk-components.yaml`, `gotk-sync.yaml`, `kustomization.yaml`. |
| CON-005 | Git Branch | Only the `main` branch is tracked (`ref.branch: main`); no multi-branch strategy. |
| CON-006 | Git Hosting | GitHub via SSH (`ssh://git@github.com/...`). |
| CON-007 | No Helm Charts Currently | helm-controller is installed but no HelmRelease resources exist. |
| CON-008 | No Git Webhook Receiver | Only polling-based reconciliation (1m GitRepository, 10m Kustomization); no webhook endpoint exposed for push-based triggers. |
| CON-009 | Single Secret per Cluster | One SSH deploy key secret (`flux-system`) per cluster for Git access. |
| CON-010 | No Application Workloads | The repository currently contains only the Flux bootstrap layer. |

## Organizational Constraints

- **Single maintainer/owner** — the repository is maintained by one Platform Engineer; there is a single `main` branch workflow with no promotion flow (dev → staging → prod) (GAP-006).
- **No CI/CD pipeline** — manifests are not validated by a pipeline (kustomize build, kubeconform, flux lint) before merge (GAP-010).
- **No documented Flux upgrade procedure** — versions are pinned, but the process for upgrading Flux components is not documented (GAP-008).
- **Kind cluster configuration not versioned** — the development cluster configuration is not stored in this repository (GAP-013).

## Conventions

**Directory layout.** Every cluster follows the same layout (CON-004):

```text
clusters/
├── kind/                          # development cluster
│   └── flux-system/
│       ├── gotk-components.yaml   # Flux-generated components
│       ├── gotk-sync.yaml         # Flux-generated GitRepository + Kustomization
│       └── kustomization.yaml     # kustomize.config.k8s.io/v1beta1
└── homeserver-cluster/            # production cluster
    └── flux-system/
        ├── gotk-components.yaml
        ├── gotk-sync.yaml
        └── kustomization.yaml
```

**Flux-generated manifests.** `gotk-components.yaml` and `gotk-sync.yaml` carry the header *"This manifest was generated by flux. DO NOT EDIT."* Changes to the bootstrap manifests should be made by regenerating them with `flux bootstrap`, not by hand-editing.

**Version pinning.** The Flux version and component versions are explicitly pinned in the bootstrap manifests (NFR-009); upgrades are intentional Git commits.

**Naming conventions.** The namespace and its resources are consistently named: namespace `flux-system`, resources `flux-system` (GitRepository, Kustomization), `critical-pods-flux-system` (ResourceQuota), `cluster-reconciler-flux-system` / `crd-controller-flux-system` (RBAC), `flux-edit-flux-system` / `flux-view-flux-system` (aggregated ClusterRoles), and NetworkPolicies `allow-egress`, `allow-scraping`, `allow-webhooks`.
